# Runtime Verification: Ready Task to Development Request Execution Bridge

Runtime evidence must be captured against a safe disposable/test project, not AIverse itself.

Required evidence:

- A real bound disposable project exists.
- A Ready backlog task exists with full operator-authored content.
- Selecting the task shows the correct project/task identity and does not execute.
- Start Development creates a real Spec 138 development request.
- The durable requirements artifact contains the full task title, description, source backlog task id, project id, development request id, and preparation identity.
- Trusted ADOS execution launches through the existing path.
- The resulting run is associated with the backlog task.
- Project Status/live agent visualization reads the real associated execution state.

This is distinct from ordinary home-canvas smoke. ADOS will collect authoritative runtime evidence after implementation.
